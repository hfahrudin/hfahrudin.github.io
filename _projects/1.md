<h5 id="intro-saiva"><strong>📚 Product Introduction</strong></h5>

<ul>
    <li id="bg-intro-saiva"><p><strong>Background</strong></p>
      Sports video analysis in football uses modern technology to evaluate player and team performance, offering valuable insights that help athletes and coaches improve tactics, skills, and decision-making. Traditionally, the process involves three stages:
      <ol>
        <li>
          <strong>Data Collection</strong> – Capturing real-time or recorded match and training footage.
        </li>
        <li>
          <strong>Analysis</strong> – Examining player movements, tactics, and team dynamics.
        </li>
        <li>
          <strong>Presentation</strong> – Delivering actionable insights to coaches and players.
        </li>
      </ol>
      <p>
        It is desirable to have a <strong>one-stop</strong> solution that can enhance and streamline all three stages.
      </p>
    </li>
    <li id="goal-intro-saiva"><p><strong>Goal</strong></p>
        Our goal is to develop a <strong>comprehensive, one-stop solution</strong> that enhances every stage of the sports video analysis process:
        <ul>
          <li><strong>Stage 1: Data Collection</strong> Enhance the efficiency on collecting football match data.</li>
          <li><strong>Stage 2: Analysis</strong> Improve the depth and effectiveness of football match analysis for better game understanding.</li>
          <li><strong>Stage 3: Presentation</strong> Streamline the delivery of insights to team members for more impactful collaboration.</li>
        </ul>

    <li id="2-key-saiva">
      <p><strong>📈 Improve System Scalability</strong><br /></p>
      <strong>Problems</strong>
      <ul>
        <li>
          The legacy backend was a monolith, written without a formal framework and heavily dependent on personalized coding styles. While functional, it was difficult to maintain, test, or scale.
        </li>
        <li>
          Video analysis tasks were compute-heavy and caused latency. In its original state, the system could only support around<em> 2 concurrent users</em> per instance, creating a bottleneck for any live deployment.
        </li>
      </ul> <br/>
      <strong>Solutions</strong><br/>
      To address the challenges posed by the legacy implementation, we undertook a comprehensive architectural overhaul, focusing on:
      <ul>
        <li><u>Migration to a cloud-native environment</u>: Enabled scalability and high availability, supporting dynamic resource allocation.</li>
        <li><u>Implementation of event-driven architecture</u>: Improved system reliability and fault tolerance by decoupling components and optimizing communication.</li>
        <li><u>Dockerization and enabling horizontal scaling</u>: Removed concurrency bottlenecks, allowing the platform to support more concurrent users and enhance performance.</li>
      </ul><br/>
      <strong>My Contribution:</strong>
      <ul>
        <li>
          Led the architectural migration of the platform to a cloud-native environment, overseeing the use of container orchestration and cloud services.
        </li>
        <li>
          Designed and guided the implementation of an event-driven communication system to improve system reliability and fault tolerance.
        </li>
        <li>
          Redesigned, decoupled, and dockerized the system to enable dynamic horizontal scaling, removing prior concurrency bottlenecks.
        </li>
      </ul>
